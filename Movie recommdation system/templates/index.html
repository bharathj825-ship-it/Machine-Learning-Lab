Methodology

Complete 12-Step Machine Learning Workflow

The end-to-end engineering lifecycle implemented for this content-based recommendation system.

STEP 01
Problem Definition
Formulate movie recommendation as an unsupervised content similarity task using item metadata rather than collaborative user ratings.
STEP 02
Data Collection
Acquire TMDB 5000 movies and credits datasets containing 4,803 titles with overviews, genres, keywords, cast, and crew.
STEP 03
Data Preprocessing
Parse JSON string representations, handle missing text and release dates, deduplicate records, and normalize punctuation and casing.
STEP 04
Exploratory Data Analysis
Analyze genre frequencies, release year trends, popularity distributions, vote ratings, and missing value profiles.
STEP 05
Feature Selection
Select high-signal descriptive metadata: movie overview, genres, keywords, lead cast members, and director.
STEP 06
Feature Engineering
Construct a unified combined_features textual representation with domain-weighted genres, keywords, and entity tokens.
STEP 07
Validation Strategy
Implement query-based relevance testing measuring Genre Overlap Ratio and Jaccard similarity against a random baseline.
STEP 08
TF-IDF Vectorization
Transform natural language into a 10,000-dimensional sparse numerical vector space using unigrams and bigrams with stop-word filtering.
STEP 09
Cosine Similarity Computation
Measure inner angles between TF-IDF document vectors to quantify thematic closeness bounded strictly between 0 and 1.
STEP 10
Model Serialization
Persist fitted vectorizer, sparse matrix, and lookup tables into models/movie_recommender.pkl via Joblib.
STEP 11
Quantitative Evaluation
Evaluate top-K cosine similarity distribution, genre overlap consistency (92.8%), and baseline gain (+52.0%).
STEP 12
Inference & UI Delivery
Deliver instant, on-demand recommendations through a responsive local Flask web application with real-time similarity metrics.

Feature Representation

TF-IDF Vectorization & Feature Engineering

Transforming textual metadata into dense semantic numerical vector representations.

Why TF-IDF (Term Frequency - Inverse Document Frequency)?

Movie titles alone do not describe narrative essence. A movie titled "Gravity" or "Arrival" requires contextual plot descriptions, keywords (e.g. space exploration, astronaut, alien), and genre tags to uncover semantic similarity.

TF-IDF Formulation:
TF-IDF(t, d, D) = TF(t, d) × IDF(t, D)

Where:
• TF(t, d) = (Count of term t in document d) / (Total terms in d)
• IDF(t, D) = log [ (1 + |D|) / (1 + Count of documents containing t) ] + 1
Vector Space Dimension 10,000 Max TF-IDF Features
N-Gram Range (1, 2) Unigrams & Bigrams
Stop Words English Filtered non-informative terms
Matrix Representation Sparse CSR Efficient memory storage
Mathematics

Cosine Similarity Measure

Geometric metric calculating the cosine of the angle between high-dimensional document vectors.

Cosine Similarity(A, B) = cos(θ) = (A · B) / (||A|| × ||B||) = ∑(A_i × B_i) / [ √∑(A_i²) × √∑(B_i²) ]

Because all TF-IDF vectors are strictly non-negative, the resulting similarity score is bounded in [0.0, 1.0]:

  • 1.0 (100%): Identical metadata composition (parallel direction in vector space).
  • 0.0 (0%): Completely disjoint vocabularies sharing zero thematic tokens (orthogonal vectors).
  • On-Demand Efficiency: The query vector is compared directly against the precomputed sparse matrix in milliseconds, avoiding dense storage overhead.

⚠️ Evaluation Methodology & Known Limitations

Unlike supervised classification with ground-truth labels, content-based recommendation is an unsupervised similarity retrieval task. High cosine similarity guarantees textual and thematic alignment (e.g. recommending space exploration movies for Interstellar), but does not guarantee whether an individual viewer will emotionally like the film without personal rating history.
